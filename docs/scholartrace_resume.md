# 项目经历

## ScholarTrace 复杂学术查询智能检索系统 (华为赛题三参赛系统)

**2026.04 ~ 2026.09**

**开发技术**: Python / LangChain / FastAPI / Pydantic / SQLite

**项目介绍**:
针对科研人员面对复杂学术查询时传统搜索引擎召回率低的痛点，构建智能论文搜索Agent系统。支持多约束自然语言查询理解、自主多轮检索迭代与结构化证据输出，在 PaSa RealScholarQuery 基准测试集上 F1 达 0.068，较词法基线提升 8 倍，命中率从 10% 提升至 100%。

**项目工作**:

### 1. 设计多阶段检索架构，提升召回质量

- 设计五阶段 Agent 检索流程（查询理解 → 子查询拆分 → 并行召回 → 去重 → LLM 精排），通过结构化中间表示提取查询中的实体、方法、时间、领域等约束条件，避免检索结果偏离原始意图
- 实现保留增强式查询规划策略：保留原始有效查询的同时，智能补充缺失的检索维度，使召回标准论文数量提升 14%，F1 分数从 0.050 提升至 0.066（提升 32%）
- 针对专有名词论文召回失败问题，设计关联词召回机制，直接使用论文标题作为检索词（如 "Attention Is All You Need"），成功修复 8 条失败查询

### 2. 实现智能迭代检索与精排优化

- 实现两轮迭代检索机制：首轮观察 top-8 证据 → Agent 自动生成补充查询 → 二轮检索 → 候选合并重排
- 对比 4 种精排方案的效果与成本（LLM 生成式、跨编码器、向量检索、融合排序），LLM 精排达到最高 F1 但成本增加 47%；基于此设计快速模式与深度模式双档位，平衡检索质量与资源消耗

### 3. 搭建工程化评测体系，保证可复现性

- 设计统一的数据流转链路（查询解析 → 子查询 → 候选证据 → 排序结果 → 执行轨迹），强制要求论文元数据（标题、DOI、作者）必须来自学术数据源而非 LLM 生成，确保结构化输出 100% 准确有效
- 集成多个学术数据源 API，设计并发限流、失败指数退避重试、分层 LLM 调度（轻量模型做解析、强模型做精排）等机制，应对 API 配额限制和服务稳定性波动

### 4. 实现预算控制与成本优化

- 实现二轮检索预算控制机制：Agent 自动生成的补充查询可能与首轮重复或过于宽泛，设计自动过滤机制剔除高相似度重复查询和低信息量泛化查询，将实际执行查询数控制在预算内，避免无效资源消耗
- 设计完整的执行轨迹记录（原始问题 → 生成子查询 → 首轮观察 → 二轮决策 → 新发现论文 → 最终结果及成本明细），支持每次运行的全流程审计和成本溯源分析
